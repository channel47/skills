# Signal Tests

Five filters for separating content from noise. Every potential nugget runs through all five. Failing any one is enough to kill it or send it to the parking lot.

---

## 1. Provenance Test

**Question:** Did this come from doing something or reading about something?

| Pass | Fail |
|------|------|
| Built something and it broke in a specific way | Read about a tool and formed an opinion |
| Made a decision and lived with the consequences | Saw someone else's thread and agreed with it |
| Tested a tool on a real project with real stakes | Watched a demo and was impressed |
| Changed a workflow based on friction experienced | Heard about a workflow change secondhand |

**The rule:** First-hand only. If you didn't build it, break it, or decide it, it's commentary, not content. Commentary is fine for replies and engagement. It's not a post.

**Edge case:** Synthesizing multiple first-hand experiences into a pattern IS first-hand. "I've tested 10 tools and only use 3" passes. "I've read about 10 tools and these 3 seem best" fails.

---

## 2. Specificity Test

**Question:** Does this contain at least one concrete detail the audience can act on or remember?

| Pass | Fail |
|------|------|
| "Saved 3 hours per client per week" | "Saved a lot of time" |
| "Deleted staging twice before it worked" | "Had some issues at first" |
| "Switched from Notion to plain markdown files" | "Changed my productivity setup" |
| "25+ accounts running this workflow" | "Many clients using this" |

**The rule:** Vague observations fail. The reader should walk away with at least one specific thing: a number, a tool name, a failure mode, a decision, a timeline.

**Sharpening trick:** If a nugget fails specificity, ask "what exactly?" three times. "AI tools are changing my workflow" → What tools? → "Claude Code" → What changed? → "I stopped writing boilerplate" → What boilerplate specifically? → "Google Ads campaign structure. Used to take 2 hours, now takes 15 minutes." That last version passes.

---

## 3. Replaceability Test

**Question:** Could any other newsletter/account in this space have posted this?

| Pass | Fail |
|------|------|
| Insight from a specific build nobody else did | General observation about AI trends |
| Opinion backed by a unique workflow | Hot take that requires no experience |
| Data from a specific use case | Restating conventional wisdom |
| Failure story with specific technical details | "Things don't always work the first time" |

**The rule:** If you can swap in any other builder's name and the post still works, it's not differentiated enough. The content should be impossible to write without the user's specific experience.

**Kill-on-sight versions:** "AI is changing everything," "the future of work is here," "5 things I learned about [broad topic]," anything that could be a LinkedIn template fill-in-the-blank.

---

## 4. Tension Test

**Question:** Is there a gap between expectation and reality that makes this interesting?

| Pass | Fail |
|------|------|
| Tool that's popular but didn't work for a specific use case | Tool that's popular and worked as expected |
| Process that looks simple but has hidden complexity | Process that was straightforward |
| Conventional wisdom that turned out wrong in practice | Conventional wisdom confirmed |
| Result that surprised (better or worse than expected) | Result that matched expectations |

**The rule:** Tension drives engagement. No tension, no post. The gap can be between: what people assume and what's true, the demo and the build, the plan and the outcome, the hype and the receipts, what's said publicly and what happens in practice.

**Note:** Tension doesn't mean negativity. "I expected this to take a week and it took a day" is tension too. Positive surprises work.

---

## 5. "So What" Test

**Question:** Why does this matter to someone who isn't the user?

| Pass | Fail |
|------|------|
| "This workflow applies to anyone managing 10+ ad accounts" | "I changed how I manage my accounts" |
| "This failure mode will hit anyone using agents for deploys" | "My agent broke something" |
| "This trade-off exists in every tool evaluation" | "I picked tool A over tool B" |
| "This gap between AI demos and production is industry-wide" | "My project was harder than expected" |

**The rule:** The answer to "so what" can't be "because AI is important" or "because I did it." It needs to be specific and transferable. The reader should see themselves in the content.

**The bridge sentence:** If you can't write "This matters to you because [specific reason]" in one sentence, the nugget needs more development. Send it to the parking lot.

---

## Scoring Shorthand

When presenting nuggets in the brief, use this shorthand:

- **5/5** — All tests pass. Top pick. Draft immediately.
- **4/5** — One test is borderline. Strong secondary idea. Note which test is weak.
- **3/5** — Interesting but not ready. Parking lot. Note what's missing.
- **2/5 or below** — Kill it. Not everything is content.

Don't inflate scores. A nugget that passes provenance and specificity but fails tension, replaceability, and "so what" is a 2/5. Being specific about your own experience isn't enough if nobody else would care.
